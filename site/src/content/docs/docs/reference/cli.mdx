These flags work with every command:

| Flag | Default | Meaning |
| --- | --- | --- |
| `--home` | `~/.selfaction`, or `$SELFACTION_HOME` | Data directory |
| `-v`, `--verbose` | off | Debug logging |
| `--version` | | Print the version |

## `selfaction run [event]`

Run the repository's workflows locally in Docker. See [Run workflows locally](/docs/guides/run-locally/).

| Flag | Default | Meaning |
| --- | --- | --- |
| `-C`, `--directory` | `.` | Repository root |
| `-W`, `--workflows` | `.github/workflows` | Workflow file or directory |
| `-j`, `--job` | | Run only this job id |
| `-l`, `--list` | | List the jobs that would run |
| `-e`, `--eventpath` | | Event payload JSON file |
| `-P`, `--platform` | | `label=image` for `runs-on`; image `-self-hosted` runs on this machine. Repeatable |
| `-s`, `--secret` | | `KEY=VALUE`, or `KEY` to read from the environment. Repeatable |
| `--var` | | Configuration variable `KEY=VALUE`. Repeatable |
| `--env` | | Environment variable `KEY=VALUE`. Repeatable |
| `--matrix` | | Only run matrix combinations with `key:value`. Repeatable |
| `--container-architecture` | | Job container platform, such as `linux/amd64` |
| `--concurrency` | CPU count | Maximum parallel jobs |
| `--pull` | off | Always pull job images |
| `--cache-dir` | `<home>/cache` | Local cache store |
| `--cache-url` | | Use a cache server, `http://host:port/<token>`, instead of the local store |
| `--no-cache` | off | Disable `actions/cache` support |
| `--artifacts` | on | Serve `actions/upload-artifact`, stored in `<home>/artifacts` |

## `selfaction cache`

All cache commands take `--dir`, the store directory, which defaults to `<home>/cache`.

### `cache serve`

Run a cache server. See [Share a cache server](/docs/guides/cache-server/).

| Flag | Default | Meaning |
| --- | --- | --- |
| `--addr` | `:7979` | Listen address |
| `--token` | generated, kept in `<dir>/token` | Access token in cache URLs. Also `$SELFACTION_CACHE_TOKEN` |
| `--external-url` | the host the job connected to | Public base URL for download links |
| `--gc-interval` | `10m` | How often to apply the retention policy |
| `--ttl` | `168h` | Evict entries unused for this long; `0` never |
| `--max-repo-size` | `10GB` | Per-repository cap, least recently used evicted first; `0` none |
| `--max-total-size` | `0` | Whole-store cap; `0` none |

### `cache ls`

List entries. Filters: `--repo owner/repo`, `--key prefix`, `--unused-for duration`.

### `cache rm <id>...`

Delete entries by id.

### `cache prune`

Delete entries matching the same filters as `ls`. Requires at least one filter, or `--all`. `--dry-run` shows what would be deleted.

### `cache gc`

Apply the retention policy now. Takes `--ttl`, `--max-repo-size` and `--max-total-size`, with the same defaults as `serve`.

## `selfaction agent`

### `agent start`

Register runners and run jobs until stopped. See [Use your machine as a GitHub runner](/docs/guides/runner-agent/).

| Flag | Default | Meaning |
| --- | --- | --- |
| `--repo` | | Serve one repository, `owner/repo` |
| `--org` | | Serve every repository in an organization |
| `-l`, `--labels` | | Extra runner labels, comma separated |
| `-n`, `--slots` | `1` | Concurrent jobs |
| `--mode` | `host` | `host` runs jobs on this machine; `docker` runs each in a fresh runner container |
| `--name` | this machine's host name | Runner name prefix |
| `--runner-group` | `1` (Default) | Runner group id |
| `--runner-version` | latest | `actions/runner` version for host mode |
| `--share-home` | off | Host mode: run jobs with your own `HOME` |
| `--image` | `ghcr.io/actions/actions-runner:latest` | Runner image for Docker mode |
| `--docker-socket` | off | Docker mode: give jobs the host's Docker daemon |
| `--token` | | GitHub token |
| `--token-file` | | Read the GitHub token from this file |
| `--github-api` | `https://api.github.com` | API base; for GitHub Enterprise Server, `https://<host>/api/v3` |

Without `--token` or `--token-file`, the agent uses `$SELFACTION_GITHUB_TOKEN`, then `$GITHUB_TOKEN`, then your GitHub CLI login.

### `agent install`

Install `agent start`, with the same flags, as a service: launchd on macOS, `systemd --user` on Linux.

### `agent uninstall`

Stop and remove the service.

### `agent clean`

Free disk used by the agent. Run it while the agent is stopped.

| Flag | Default | Meaning |
| --- | --- | --- |
| `--tools` | off | Also delete tool caches and slot home directories |
| `--runners` | off | Delete runner installs and downloads entirely |
| `--docker` | off | Also prune Docker objects older than `--docker-age`, on the whole Docker host |
| `--docker-age` | `72h` | Age for `--docker` |

## `selfaction server`

Take GitHub webhooks and queue the workflows they trigger for workers. See [Run workflows from webhooks](/docs/guides/server/).

| Flag | Default | Meaning |
| --- | --- | --- |
| `--addr` | `:8080` | Listen address |
| `--external-url` | `http://<this machine's IP>:<port>` | Public base URL for the webhook, status links and the workers' cache |
| `--webhook-secret` | | Required. Also `$SELFACTION_WEBHOOK_SECRET` |
| `--worker-token` | generated, kept in `<home>/server/worker-token` | Token workers authenticate with. Also `$SELFACTION_WORKER_TOKEN` |
| `--github-token` | | GitHub token |
| `--token-file` | | Read the GitHub token from this file |
| `--github-api` | `https://api.github.com` | API base; for GitHub Enterprise Server, `https://<host>/api/v3` |
| `--workflows` | `.github/workflows` | Workflow directory in each repository |
| `--allow-forks` | off | Run pull requests from forks |
| `--no-cache` | off | Don't serve `actions/cache` to workers |
| `--ttl` | `168h` | Cache: evict entries unused for this long; `0` never |
| `--max-repo-size` | `10GB` | Cache: per-repository cap, least recently used evicted first; `0` none |
| `--max-total-size` | `0` | Cache: whole-store cap; `0` none |

Without `--github-token` or `--token-file`, the server uses `$SELFACTION_GITHUB_TOKEN`, then `$GITHUB_TOKEN`, then your GitHub CLI login. Its data lives in `<home>/server`.

### `server jobs`

List the latest 100 jobs. Takes `--server`, default `http://localhost:8080`, and `--token`, the worker token, which defaults to `$SELFACTION_WORKER_TOKEN`, then `<home>/server/worker-token`.

### `server cancel <job id>...`

Cancel queued or running jobs. Takes the same flags as `server jobs`.

## `selfaction worker`

Claim jobs from a server and run them with the act engine. See [Run workflows from webhooks](/docs/guides/server/#workers-and-labels).

| Flag | Default | Meaning |
| --- | --- | --- |
| `--server` | | Server base URL. Required |
| `--token` | `$SELFACTION_WORKER_TOKEN`, then `<home>/server/worker-token` | The server's worker token |
| `--name` | this machine's host name | Worker name; slot n reports as `<name>-<n>` |
| `-n`, `--slots` | `1` | Concurrent jobs |
| `-l`, `--labels` | | Extra `runs-on` labels, comma separated |
| `-P`, `--platform` | | `label=image` for `runs-on`, which also serves the label; image `-self-hosted` runs on this machine. Repeatable |
| `--container-architecture` | | Job container platform, such as `linux/amd64` |
| `--job-timeout` | `6h` | Cancel a job that runs longer |

Workspaces, the fallback cache and artifacts live in `<home>/worker`.
