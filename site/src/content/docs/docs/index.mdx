selfaction runs GitHub Actions workflows on hardware you control. It is one binary with four jobs:

| You want to… | Use | What happens |
| --- | --- | --- |
| Try a workflow before pushing it | `selfaction run` | The workflow runs on this machine in Docker, using the [act](https://github.com/nektos/act) engine. `actions/cache` and artifacts work. |
| Have GitHub send jobs to your machine | `selfaction agent` | Your machine registers as a GitHub self-hosted runner. Jobs with `runs-on: [self-hosted, <label>]` run here using GitHub's official runner. |
| Run CI from webhooks, without GitHub's runner service | `selfaction server` and `selfaction worker` | GitHub sends webhooks to your server, which queues the workflows they trigger. Workers run them with the act engine and report back as commit statuses. |
| Share a dependency cache across runs and machines | `selfaction cache` | A cache server that speaks the `actions/cache` protocol, with per-repository storage and cleanup tools. |

Your workflow files do not change. Marketplace actions such as `actions/checkout`, `actions/setup-go` and `actions/cache` work as they are.

## When each mode fits

**`run`** is for the edit, run, fix loop. Nothing is pushed and nothing reaches GitHub. It is also the fastest way to check that a workflow still works after you change it.

**`agent`** is for real CI. GitHub still decides when a workflow runs, shows the logs and reports the result on your pull request. Only the execution moves to your machine. Use it when hosted runners are too slow, too expensive, lack the hardware you need (Apple silicon, a GPU, lots of RAM) or are unavailable to your account.

**`server`** is CI without GitHub Actions. GitHub only sends webhooks: the queue, the logs and the machines are yours, and results show on commits and pull requests as statuses. It works for repositories where GitHub Actions is turned off or unavailable, at the cost of some compatibility: only `push` and `pull_request` start jobs, and repository secrets are not passed to jobs.

**`cache`** is for teams. One `selfaction cache serve` instance can back every `selfaction run` on a network, so the second person to build a branch gets the first person's dependencies.
